# United States 2025 federal working papers — candidate .3

This is a concrete partial country adapter using the existing `FinanceTaxIntake`, reviewed `FinanceTaxFact`, authority-reference and `FinanceTaxEvaluation` contracts. It does not register a package: the common registry requires attested **full-return** coverage. `enabled`, `registryEligible`, and `complete` remain false. Canada remains the first release gate. Filing certification and electronic filing are outside this calculation/export scope.

`evaluateUs2025WorkingPapers(intake)` returns immutable, JSON-serializable generic form rows plus an exact-rational dependency trace, input/output hashes, source-fact bindings and an explicit incomplete status. There is no browser principal, database write, client-supplied tax result, model rule generation, or invented reviewer identity. A future trusted service must authorize the private case and bind its actual locked snapshot hash; `inputHash` is a canonical input hash, not that persisted snapshot hash.

## Exact calculation scope

The scope is `US / US-FED / sole-proprietor / 2025 / income-tax-return / 1040-2025`. `US-FED` expressly excludes state and local calculations; it does not imply state exemption. One cash-method ordinary service business, single full-year domestic resident under65, ordinary W-2 totals and zero or positive business profit. Every monetary field, including zero W-2 boxes, must be a reviewed nonnegative USD decimal with at most two decimal places. Expenses are reviewed deductible amounts, not an automatic determination that a receipt is deductible. Each line aggregate must retain original cents; `roundUsdLine` demonstrates add-before-round for upstream line aggregation.

All exclusions in `US_2025_EXCLUSIONS` and `US_RETURN_REQUIRED_FACTS` require explicit reviewed values. Missing, unreviewed, disputed, extra unmapped, malformed, mismatched scope and unbound ledger facts block calculation. Business losses block rather than skipping at-risk, passive loss or carryforward controls. Fractional-dollar input is retained; no whole-dollar-only case restriction is used. High taxable income remains an explicit unsupported branch requiring Form8995-A, not a silently truncated return.

Candidate .2 added reviewed facts for the standard-deduction election, qualified domestic trade, prior QBI losses/cooperatives/REIT/PTP, Schedule1-A eligibility, other credit claims/taxes, AMT preferences, basic childless EIC eligibility and payment allocation. It accepts only age bands `under25` or `25-to-64`; valid employment SSN and main US home determine childless EIC. Prior EIC disallowance or excluded wages require unsupported schedules rather than assumed eligibility. The standard deduction is an explicit election, not an optimization against an unimplemented ScheduleA.

## Reporting policy and validation boundary

The captured 2025 1040 instructions permit a whole-dollar election for the return and schedules, with less-than-50-cent amounts dropped, 50 cents upward, and original cents retained when adding amounts for a line. This adapter requires that election. Federal version2025.4 retains exact pre-entry arithmetic in each trace row and makes downstream form references consume the entered whole-dollar value. Original source cents are aggregated before entering a single line (for example combined W-2 boxes3+7); sums of already-entered form lines use those entered values. Tax-table and EIC-table lookups explicitly use the elected reported lookup amount, as their headings direct. At displayed taxable income $100,000, the tax computation worksheet replaces the table. Signed Form6251 line1b/Form8995 line11 preserve the sign while applying the magnitude rounding policy.

Entered component lines now reconcile to downstream sum lines under the elected whole-dollar policy. For example SE10=1145 and11=268 produce SE12=1413; SE13=round(1413×50%)=707, and the S1/F1040 deduction copies707. The prior .3 package carried hidden fractions into downstream references; historical .3 artifacts must retain their original hashes and version and must not be relabeled as .4. Final settlement is explicitly reconciled from reported tax24, payments33 and penalty38: the 1040 instructions require35a +36 +38 =34 when the overpayment covers the penalty; any excess penalty is added to37. The IRS publication examples validate components, not all intermediate reporting conventions. Complete-return independent reporting validation remains a release gate, including signed amounts and rounded-display threshold boundaries. The adapter does not silently treat those wider validation gates as satisfied.
