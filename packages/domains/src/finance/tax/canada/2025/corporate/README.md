# Canada 2025 corporate return review workflow

This is an **incomplete, disabled review pipeline**, not a complete T2 package, certified software, return filing, or a country registry activation. It accepts structured case facts, validates supported conditions and financial-statement relationships, calculates exact amounts, constructs a form dependency graph, and exports deterministic JSON for private review. Each monetary field preserves its exact value. `reportableAmount` is populated only when official fillable-form precision permits lossless encoding and every reporting dependency is resolved; fractional rounding remains unresolved. These individual encodings are not a complete filing artifact. Unsupported facts stop the pipeline before it emits a tax calculation.

## Implemented case coverage

Canadian-resident Ontario-only CCPC throughout the full calendar 2025 tax year; standalone in current and prior years; one Canadian-resident individual owns all common shares, with no preferred shares. Positive ordinary active-business income through $500,000; prior taxable capital through $10 million and no prior adjusted aggregate investment income. Existing corporation with unchanged identity addresses and accounting method, no acquisition/amalgamation/first/final return, special Ontario type change, foreign activity, capital assets, inventory, loss pools, elections, other tax adjustments, other provincial credits, or additional T2 attachment triggers.

This is an explicit **partial implementation of standalone corporations**, not a substitute for the original full corporate goal. General-rate income, losses, CCA, associated corporations, investment income, foreign reporting, dividends, elections, other provinces, non-calendar periods, and many ordinary business balance-sheet classifications remain unsupported. Each T2 E(25) attachment question that would introduce these schedules is separately declared, with `null` and missing facts blocked; no model-inferred default No is accepted.

The financial adapter takes complete opening/closing statements, trade revenue, enumerated ordinary deductible expense classifications, current book tax provision, notes, actual Schedule141 preparer facts, prior-year tax facts and instalments. It checks assets = liabilities + equity for each period and reconciles retained earnings through after-tax income. It never silently writes a calculated tax provision into the supplied statements. A provision difference is retained and flagged for review. GIFI monetary amounts retain source cents; GIFI's no-cents filing rule is not silently applied with an unverified rounding method.

The evaluation graph uses exact integer arithmetic at six decimal places, which exactly represents the input cents and every implemented rate multiplication (38%, 10%, 19%, 11.5%, 8.3%). Outputs include a reduced numerator/denominator and exact decimal. No binary floating-point money, implicit clock, tax-year inference or rounding is used. The final JSON contains the full normalized intake, supplied case revision/hash, evidence references, calculated forms, source captures and blockers. Replaying its intake yields the identical export bytes/hash. The snapshot binding is a caller-supplied provenance claim: the durable authorized case service must verify it before invoking this pure library; this library grants no permissions and does not load private cases itself.

## Proven field precision and remaining mapping gaps

The eight captured official fillable PDFs contain 1,618 XFA field instances. `scripts/capture-xfa.py` reproduces the complete inventory and compact TypeScript catalog without network access. Every field binding retains its source hash, ordinal, SOM path, display picture, and numeric validator evidence. Ordinals distinguish duplicate SOM paths. The catalog is an inventory, not a claim that every field is required for this case.

T2, S1, S5, S500 and GIFI monetary controls use whole-dollar numeric validation with a 12-digit limit. The Ontario base rate accepts one decimal percentage, the Ontario deduction factor four decimals, and Schedule50 shareholder percentages two decimals. GIFI entries bind both the selected code and its companion amount field. The pipeline maps every implemented monetary field and the rate/factor/share percentage fields to this evidence, and lists unclassified inventory fields and unmapped logical fields for further review.

Lossless encoding performs no rounding: 100.00 can encode as 100 in an integer field, while 100.01, 100.49, 100.50 and 100.51 remain unresolved. An exact integer subtotal also remains unresolved if an upstream reporting field requires rounding. A shared `roundNumber` PDF helper is not invoked by these monetary controls, so its existence is not authority for an annual return rounding algorithm. Public fillable PDF precision is not a certified COR/EFILE specification.

Exports include package version `2025.7` and a hash of the versioned review manifest (coverage, arithmetic/reporting algorithm identifiers, form graph and source captures). This is manifest provenance, not an executable-source hash or certification. Future rule changes must update the package version. The authorized durable adapter must still bind actual private-case inputs and package selection server-side.

## Remaining completion blockers

1. **T2/GIFI reporting rounding is unresolved.** RC4088 “Reporting in dollars” explicitly says no cents and illustrates $10,500.75→10501. It does not establish the general T2 tie rule, negative rounding or cross-form balance-reconciliation procedure. T4012 E(25), T2 E(25), Schedule500 and public developer/form guidance reviewed here do not resolve those points. Payroll T4127's factor named T2 is provincial payroll tax, not a corporation return; its rounding rule must not be borrowed. All fractional cases are retained and calculated, not excluded to make whole-dollar examples look complete.
2. **Candidate field coverage is independently exercised, not country-wide coverage.** The2025.7 standard fixture resolves every captured control as populated or fact-backed inapplicable and verifies mandatory fixed GIFI controls directly. Unpublished or absent text constraints are not invented as blockers. Other corporation regimes and unsupported intake cases still stop explicitly; this does not activate the country package.

## Out-of-scope filing

**CRA-certified filing is unavailable and is not an acceptance gate for this project.** No COR generation, certified barcode, electronic submission, signed certification, preparer authorization or CRA validation service is implemented. The ordinary covered corporation is generally required to file electronically. JSON is a private review artifact, never a filing artifact.

Public developer guidance IC97-2 paragraph13 states that Early Access is password protected and requires an NDA; no access request or external message was sent. Resolving rounding may require the relevant CRA corporate software specification, not another jurisdiction's rules. No readiness or registry change should occur until the calculation, applicable form-field coverage and independent validation blockers above, and the broader corporate scope, are resolved. Electronic submission and filing certification remain explicitly outside the approved scope.

## T2 reductions and refundable-tax pools

Version2025.4 implements the CCPC general tax reduction on page5 (A–I and638), refundable portion of PartI tax on page6 (A–M and450), and page7 ERDTOH/NERDTOH rollforwards plus dividend-refund intermediates AA–JJ and transfer784. Authority is captured T2 E(25) pages5–7 and T4012 E(25)'s refundable dividend tax on hand instructions. Ratios use exact integers: 30 2/3%=23/75, 38 1/3%=23/60, and the foreign-credit multiplier75/29. No annual rounding is introduced.

For current supported ordinary ABI within the SBD limit, the general reduction base and current refundable PartI tax are zero. Current dividends, PartIV tax, foreign credits, transfers and investment income are absent only because their explicit questionnaire conditions are validated. Historical pools can be nonzero, including fractional balances. The required `priorYear.refundableTaxHistory` records preceding ERDTOH/NERDTOH, prior eligible/noneligible dividend refunds and a source-reference ID. Negative prior NERDTOH and negative resulting pools use the form's explicit zero floors. Prior refunds reduce historical pools even when no current dividends are paid. The separate non-CCPC general reduction section is explicitly inapplicable under the form instruction.

Independent fixtures verify 1500−400=1100 eligible and2300−700=1600 noneligible carryforwards, fractional100.51−0.02=100.49, negative-input/output floors, zero current dividend refunds, exact field dependencies and missing-history/evidence rejection. Source monetary encodings remain subject to the existing rounding dependency checks.

Remaining field gaps are enumerated in each run's `fieldCoverage.unresolvedFields`: remaining duplicate copy controls and unused or conditional S1/S5/GIFI sections, together with field validation. Current-year dividend/investment/foreign activity and other broader corporation regimes remain unsupported rather than being inferred from these pool calculations. Filing certification remains outside scope.

Explicit `declarations.noOtherFederalCredits` supports zero entries for unclaimed federal credits. `taxWithholding` records actual amount, gross payments and source-reference ID. Positive withholding requires source evidence and cannot exceed the payments or gross trade income. It is a credit, never an expense reducing reported gross trade sales. The package still does not assert complete return coverage: remaining source controls/applicability, required character/length validation and authoritative rounding must be resolved, along with the broader corporation regimes explicitly outside the currently implemented calculation case. No readiness activation accompanies these mappings.

## Private case preparation and durable working runs

The trusted private-case adapter now connects this engine to the same declaration, source review, immutable run/schedule, output review and CSV export path used for personal cases. The explicit corporate workflow is `ca-on-2025-corporate-working-papers`; its exact scope is CA / CA-ON / corporation /2025 / income-tax-return / `T2-2025_GIFI-2025_ON-2025`. This is a working-package binding, not a released full-return manifest. All country registries remain unavailable.

The server selects the adapter from the locked case scope and checks the requested workflow/package version. Identity keys retain the existing private `identity.` prefix. Required scalar questions derive from the strict corporate intake schema; nullable answers require an explicit value or `none`, and bounded collection facts use explicit lists (including `[]` when empty). They remain constrained by the existing declaration text limit; longer collection evidence needs a future structured attachment adapter rather than truncation. No missing collection, tax-history balance or declaration is guessed. Binding case ID/revision/hash and the prior-history/withholding source references are derived server-side from the exact reviewed sources. Client-supplied rule packages, calculated outputs, reviewer IDs and authority claims are rejected by the existing API contracts.

Both packages share the same current membership/case-grant/source-revocation checks, CAS/idempotency receipts and normalized immutable schedules. The corporate engine manifest and separate input/output adapter versions are committed by the durable package hash. Existing personal output bodies and hashes remain unchanged. Public run details contain numeric form fields and safe issue/provenance metadata; raw corporate identity remains in authorized human declaration review and export. Whole-dollar paper field encodings remain whole-dollar strings with an explicit published-precision status; they are not converted into an invented cent-format reporting rule.

The authenticated CSV includes all corporate form values, exact input/run/package/source hashes and the corporate review-export hash. It is labelled incomplete with taxpayer signing unperformed. Output review never changes `complete`, `enabled` or `reportable` to true. Filing and signing are not used as artificial calculation-completion gates; the engine's actual remaining rounding proof is retained.
